# Архитектура бэкенда

Стек: Go, только стандартная библиотека (`net/http`, `encoding/json`). Данные
живут в памяти процесса, базы нет.

Бэкенд устроен так же, как фронтенд
([`../Homework_1/ARCHITECTURE.md`](../Homework_1/ARCHITECTURE.md)): тонкий
слой, который принимает событие (хендлер ↔ презентер), таски с
бизнес-логикой, сторы с состоянием и клиент внешнего API. Отличия идут от
устройства Go и описаны ниже.

Эталонный пример фичи: [`favorites/`](favorites).

## Пример структуры

```
main.go                 ← точка входа: роуты фич, CORS, порт; логики нет
constants.go            ← порт и origins по умолчанию
arch_test.go            ← проверка правил этого файла (+ arch_*_test.go)
web/                    ← общий HTTP-слой: JSON, ошибки → статусы, CORS
tvmaze/                 ← общий клиент TVmaze с кешем (нужен shows и favorites)
  client.go             ← SearchShows, GetShow
  cache_store.go        ← кеш ответов, 5 минут
  show.go               ← ответ TVmaze → наш Show
  types.go  constants.go  errors.go
health/
  handler.go            ← GET /api/health — прогрев сервера на Render
shows/                  ← фича «поиск сериалов»
  handler.go
  search_shows.go       ← таска
  utils.go              ← фильтр по жанру, подсчёт жанров, пагинация
  types.go  constants.go
favorites/              ← фича «избранное»
  handler.go
  handler_params.go     ← разбор X-Client-Id и id из запроса
  store.go              ← избранное в памяти
  add_favorite.go  remove_favorites.go  list_favorites.go
  types.go  constants.go
```

## 1. Фронтенд и бэкенд

- **Бэкенд владеет данными и бизнес-правилами.** Он ходит в TVmaze и кеширует
  ответы, приводит их к нашему `Show`, фильтрует по жанру, считает жанры, режет
  выдачу на страницы и хранит избранное. Фронт получает готовый результат и
  ничего не пересчитывает.
- **Фронтенд отвечает за отображение и UI-состояние**: что открыто, что
  подсвечено, какой текст показать, что пользователь отметил, но ещё не
  подтвердил.
- **Тексты для людей бэкенд не отдаёт.** В ответе только данные и коды ошибок
  (`rateLimit`, `notFound`), переводит их фронт. Значения из TVmaze (`Drama`)
  уходят как есть.

## 2. Фича

Фича — пакет верхнего уровня, он же ресурс API: `shows` → `/api/shows`. Внутри
пакет плоский. Роль файла видна по имени.

| Файл                                | Назначение                             | На фронте                |
| ----------------------------------- | -------------------------------------- | ------------------------ |
| `handler.go`                        | `Register(mux)` и хендлеры фичи        | View + Presenter         |
| `handler_*.go`                      | Части хендлера: разбор параметров      | `logic/useXxx.ts`        |
| `verb_noun.go`                      | Таска — бизнес-логика                  | `logic/tasks/verb.ts`    |
| `store.go`, `*_store.go`            | Стор                                   | `logic/xxxStore.ts`      |
| `types.go`, `constants.go`          | Типы и константы пакета                | `types.ts`, `constants.ts` |
| `utils.go`, `errors.go`             | Чистые помощники, ошибки пакета        | `logic/utils.ts`         |

**Любой `.go` файл — не больше 120 строк.** Упёрся — в файле смешаны
ответственности, разнеси их по таскам, `handler_*.go` или `utils.go`.

### Хендлер — `handler.go`

- `Register(mux)` вешает роуты фичи, его вызывает `main.go`.
- Разбирает запрос: путь, query, заголовки. Проверяет только формат (число,
  непустой id) и отвечает `web.ErrBadRequest`.
- Вызывает **одну таску**, передаёт ей `r.Context()` и разобранные значения.
- Отвечает через `web.WriteJSON`, ошибки отдаёт в `web.WriteError`.
- **Нельзя:** бизнес-правила, обращение к стору, вызовы `tvmaze`. В отличие от
  презентера, хендлер стор и не читает: любой ответ сервера — результат таски.

### Таски

Таска — вариант использования: «найти сериалы», «добавить в избранное».

- Функция-глагол, одна таска — один файл: `addFavorite` → `add_favorite.go`.
  В файле таски — только она. Помощники — в `utils.go`.
- Не зависит от HTTP: не импортирует `net/http` и `web`. Принимает
  `context.Context`, если ходит в сеть, и обычные значения.
- Возвращает результат и `error`, не паникует, не логирует. Ошибку
  оборачивает через `%w`, статус выбирает `web.WriteError`.
- Со стором говорит через его методы, поля не трогает. Несколько сторов
  связывает таска, а не сторы друг друга.
- Во внешний API ходит через функции `tvmaze`, `http.Client` сама не создаёт.
- Может вызывать другие таски своего пакета.

## 3. Дерево и общие пакеты

Пакет `main` нельзя импортировать, поэтому корень модуля — это и есть «App»:
фичи и общие пакеты лежат в нём рядом, дерево плоское.

- **Общий пакет** (`web`, `tvmaze`) — аналог `src/components` и `src/logic`:
  код, нужный двум и более фичам. Хендлеров в нём нет.
- Код, нужный одной фиче, лежит в ней. Понадобился второй фиче — переезжает в
  общий пакет. Никому не нужен — удаляется.
- **Импорт:** фича → общие пакеты. Фича не импортирует другую фичу, общий пакет
  не импортирует фичи. Фичи подключает только `main.go`.
- **Экспорт** (заглавная буква) — только то, что берут другие пакеты:
  `Register`, `tvmaze.SearchShows`, `tvmaze.Show`, `web.WriteJSON`. Таски,
  сторы и типы фичи — со строчной буквы.

## 4. Сторы

- Стор — синглтон пакета: тип со строчной буквы и единственный экземпляр в
  переменной пакета, рядом конструктор для тестов.

  ```go
  var store = newFavoritesStore()
  ```
- Данные лежат в обычной `map` — это и есть `const favorite = {}` из задания.
  Хендлеры работают параллельно, поэтому каждый метод берёт `sync.Mutex`.
- Методы — простые экшены (`add`, `remove`, `list`). Наружу отдают копии, а не
  внутренние `map` и срезы.
- Стор не знает про HTTP, TVmaze и другие сторы.
- Память живёт до перезапуска: деплой или сон на Render её стирают. Это
  осознанно, базы данных в задании нет.

## 5. Внешний API и кеш

- В TVmaze ходит только пакет `tvmaze`. Наружу — функции с нашими типами
  (`SearchShows`, `GetShow` → `Show`). Сырые типы TVmaze (`apiShow`) не
  экспортируются.
- **Кеш — деталь клиента.** Ключ — URL запроса к TVmaze, срок — 5 минут. Свежая
  запись есть — отдаём её. Нет или устарела — идём в TVmaze и перезаписываем.
  Кешируются только успешные ответы. Таски про кеш не знают.
- Ошибки TVmaze превращаются в `tvmaze.ErrNotFound`, `ErrRateLimit`,
  `ErrUnavailable`.

## 6. HTTP API

- Все роуты под `/api`, ответы — JSON с полями в camelCase. Пустой список —
  `[]`, не `null`.
- Ошибка — `{"error": {"code": "…"}}` и статус: `badRequest` 400,
  `notFound` 404, `rateLimit` 429, `upstream` 502, `internal` 500. Таблица
  живёт в `web.WriteError`.
- Избранное принадлежит браузеру: анонимный id в заголовке `X-Client-Id`.
- CORS разрешён origin-ам из `ALLOWED_ORIGINS`.

| Метод    | Путь                         | Ответ                                                   |
| -------- | ---------------------------- | ------------------------------------------------------- |
| `GET`    | `/api/health`                | `{status}`                                              |
| `GET`    | `/api/shows?q=&genre=&page=` | `{items, genres, total, found, page, pageCount}`        |
| `GET`    | `/api/favorites`             | `{items}` — свежие сверху                               |
| `PUT`    | `/api/favorites/{id}`        | `{items}`, повторный вызов ничего не меняет             |
| `DELETE` | `/api/favorites?ids=1,2`     | `{items}`, несколько id за раз                          |

## 7. Комментарии

Не пишем совсем, как и на фронте, включая Go-doc у экспортов. Непонятно без
комментария — переименуй или разбей код.

## 8. Именование

| Что     | Пример                                                       |
| ------- | ------------------------------------------------------------ |
| Пакет   | `favorites`: строчные буквы, одно слово                      |
| Файл    | snake_case: `add_favorite.go`                                |
| Таска   | `addFavorite` в `add_favorite.go`                            |
| Стор    | `store.go`: тип `favoritesStore`, экземпляр `store`          |
| Ошибка  | `ErrNotFound` в `errors.go`                                  |

## 9. Проверки

`make check` — `gofmt`, `go vet` и `go test ./...`. Правила этого файла
проверяет `arch_test.go`:

- файл не длиннее 120 строк, комментариев нет;
- `const` — только в `constants.go`, `type` — в `types.go` и файлах сторов;
- фичи импортирует только `main.go`;
- файл таски — одна функция с именем файла, без `net/http` и `web`;
- `handler*.go` не обращается к переменным стора.
